Méthodologies par type de binaire — par où commencer et quoi utiliser

Toujours commencer par

Quelle que soit la cible, commence par file ./binaire pour identifier le type, puis strings ./binaire | grep -i [mot clé]. C'est souvent suffisant pour les challenges simples.

Workflows par type

ELF Linux (x86/x64) débutant
  • 01Identifier avec file ./binaire
  • 02Chercher les strings avec strings | grep -i [mot clé]
  • 03Ouvrir dans Ghidra → chercher main()
  • 04Trouver la logique de validation
  • 05Inverser les opérations en Python
file strings ghidra python3
ELF 32 bits (x86) débutant
  • 01Vérifier avec file → ELF 32-bit
  • 02Même workflow que ELF x64
file ghidra
.NET / C# (PE) débutant
  • 01Décompiler avec ilspycmd ./challenge.exe -o ./out/
  • 02Chercher la logique de validation
  • 03Inverser les opérations en Python
ilspycmd python3
APK Android (Java) débutant
  • 01Décompiler avec jadx ./challenge.apk
  • 02Trouver le package principal dans AndroidManifest.xml
  • 03Chercher MainActivity → logique de validation
  • 04Inverser les opérations en Python
jadx jadx-gui python3
APK Flutter intermédiaire
  • 01Extraire avec jadx challenge.apk
  • 02Release : analyser lib/arm64-v8a/libapp.so avec Ghidra
  • 03Debug : chercher kernel_blob.bin dans assets
  • 04Inverser les opérations en Python
jadx reflutter ghidra python3
WebAssembly (WASM) intermédiaire
  • 01Convertir : wasm2wat challenge.wasm -o out.wat
  • 02Chercher dans les sections data (hashes, strings, flags)
  • 03Analyser la logique de validation dans le .wat
  • 04Inverser les opérations en Python
wasm2wat python3
ARM / MIPS intermédiaire
  • 01Chercher les strings avec strings | grep -i [mot clé]
  • 02Analyser statiquement dans Ghidra (supporte ARM/MIPS)
  • 03Analyser la logique de validation
  • 04Pour exécuter : qemu-arm ./binaire ou qemu-mips
  • 05Inverser les opérations en Python
ghidra qemu-arm qemu-mips python3
Golang intermédiaire
  • 01Chercher les strings avec strings | grep -i [mot clé]
  • 02Analyser statiquement dans Ghidra → chercher les fonctions main.*
  • 03Analyser la logique de validation
  • 04Inverser les opérations en Python
ghidra python3
Godot (GDScript / C#) intermédiaire
  • 01Extraire le .pck : gdre_tools --recover ./challenge.pck
  • 02GDScript → lire les fichiers .gd extraits
  • 03C# → décompiler la DLL avec ilspycmd
  • 04Chercher la logique de validation du flag
  • 05Inverser les opérations en Python
gdre_tools ilspycmd python3
Lua bytecode intermédiaire
  • 01Décompiler avec unlua ./challenge.luac
  • 02Analyser la logique de validation du flag
  • 03Inverser les opérations en Python
unluac python3
Windows .exe (Wine) débutant
  • 01Exécuter : wine ./challenge.exe
  • 02Si .NET → utiliser ilspycmd directement
  • 03Si natif → ouvrir dans Ghidra (PE supporté)
  • 04Analyser la logique de validation du flag
  • 05Inverser les opérations en Python
wine ghidra ilspycmd python3
Python bytecode (.pyc) débutant
  • 01Décompiler avec uncompyle6 ./challenge.pyc
  • 02Lire le code Python décompilé
  • 03Inverser les opérations en Python
uncompyle6 python3

Conseils généraux

Analyse statique vs dynamique

Commence toujours par l'analyse statique (strings, ghidra). L'analyse dynamique (gdb, strace) sert quand le code est trop complexe à lire ou obfusqué.

Quand utiliser Python

Dès que tu as compris l'algorithme, réécris-le en Python et inverse-le. C'est plus rapide que d'exécuter le binaire et de bruteforcer.

Hashes trouvés

Si tu trouves un hash MD5/SHA dans un binaire, teste-le directement sur crackstation.net ou hashes.com avant de chercher à l'inverser.
